# Java workflow application

This is a synthetic staff-workflow learning application. Issuer offers, client approval, instruction, firm acceptance, booking and settlement are simulated. The Python HTTP valuation is a real approximate model calculation. There is no institutional connection or production identity check.

## Build and run

Requirements: Docker with Compose v2+ and `just` 1.56+. Linux, macOS and native Windows PowerShell use the same recipes (Docker Desktop on Windows must use Linux containers). Java 21, Gradle and PostgreSQL run in containers. The Gradle Wrapper downloads checksum-pinned Gradle 8.14.3 on first use; dependencies require network access unless cached. Spring Boot is pinned to 3.5.16, retaining its Jackson 2 APIs. The Spring Boot 3.5.16 BOM manages dependency versions.

From this `app` directory:

```sh
just test       # All 8 tests, including 5 real PostgreSQL tests
just build      # Write build/libs/structured-products-lab-1.0.0.jar
just run        # Build/start the application, PostgreSQL and Python pricer
```

`just gradle <tasks/options>` forwards to the containerized Gradle Wrapper. All Java tests use an isolated PostgreSQL service on the private test Compose network, with the synthetic credentials `lab`/`lab-local-only`; no host database or `TEST_DB_URL` setup is required. Database tests stub pricing; the root `just journeys` exercises the actual Java–Python HTTP boundary. Test reports are written to `build/reports/tests/test/index.html`. From the repository root, `just test-db-down` removes the test database and its data.

`just run` delegates to the root `just up` and starts the complete stack. The Angular staff UI is at [localhost:4200](http://localhost:4200/workspace); see the [UI walkthrough](../docs/ui-guide.md). The application API listens on localhost:8080 and the pricer on localhost:8090. Compose supplies the internal database/pricer URLs, `/fixtures/terms` and development fault injection for the rollback exercise. Runtime configuration is in the root `compose.yaml`; the application supports `PORT`, `DB_URL`, `DB_USER`, `DB_PASSWORD`, `PRICER_URL`, `PRICER_TIMEOUT_MS`, `TERMS_DIRECTORY`, `FAULT_INJECTION`. Fault injection defaults to false in the application itself.

Health: `GET /actuator/health`. Requests accept and return `X-Correlation-ID`; malformed IDs are replaced. Structured request log fields and persisted audit records carry the ID.

## API contract

Every endpoint below starts with `/api`. IDs are UUIDs. Required fields have Java Bean Validation constraints. JSON errors contain `error`, `message`, `correlationId`. Business conflicts use 409, invalid requests 400, unknown fixtures 403, and missing resources 404. The pricer adapter maps actual HTTP timeout to 504 and remote HTTP errors/unavailability to 502.

1. `GET /templates` returns the complete versioned contracts. `POST /enquiries` accepts `{"product":"AUTOCALLABLE","clientId":"client-demo","operatorId":"staff-demo"}`; `ACCUMULATOR` is the other product. The returned enquiry includes `id`, `version`, full `terms`, `termsHash`, and explicit fixture eligibility. The frozen template fixes trade size; a changed size is an explicit new term version.
2. `POST /enquiries/{id}/rfq` accepts `{"scenarios":{"Issuer-B":"TIMEOUT"},"deadlineMillis":200}`. All three issuers fan out through one fixed three-thread pool. Per-dispatch deadlines are bounded 10–1000 ms. Modes are `OK`, `TIMEOUT`, `ERROR`, `EXPIRED`, `STALE`, `INCOMPARABLE`, `DECLINED`, `UNSUPPORTED`. Result: `{requestId,enquiryId,deadlineMillis,offers:[...],simulated:true}`. Each persisted offer includes full terms/hash, issuer, time/expiry, size, price, fee and convention. A timeout or exception is an explicit failed offer, rather than a fabricated price.
3. `GET /enquiries/{id}/comparison` returns `{basis,offers:[{offer,comparability,netUpfrontCost}],interpretation}` and persists the snapshot in an `OffersCompared` audit event. The note comparison uses fixed payoff terms and issue price percent plus an HKD fee. Accumulators use fixed strike/quantity/schedule and an HKD upfront fee. A lower upfront cost alone does not establish suitability. Invalid offers have a null comparable cost. Issuer credit information remains separate synthetic information.
4. `POST /enquiries/{id}/match` accepts `{"outcome":"UNIMPROVED"}`; alternatives are `IMPROVED`, `MATCHED`, `DECLINED`. This returns `{outcome,offer}` for an explicitly simulated Barclays response to the cheapest currently comparable external offer. It does not mandate selection or represent actual Barclays economics.
5. `POST /enquiries/{id}/selection` accepts `{offerId,rationale}` for a current comparable indicative offer. `POST /enquiries/{id}/instruction` accepts `{"authorised":true,"reference":"synthetic-instruction-1"}`. Both return the enquiry. A new selection clears the old instruction.
6. `POST /enquiries/{id}/firm` accepts `{"scenario":"OK"}`; `EXPIRED`, `DECLINED`, `STALE` permit fault drills. It returns a distinct offer with `kind:FIRM`, linked to the selected indicative offer. It is a simulated firm boundary, not live execution.
7. `POST /enquiries/{id}/accept` accepts `{offerId,idempotencyKey,failAfterTrade:false,expectedVersion:null}` and returns a trade with `state:SIMULATED_BOOKED`. Only the current instructed, available, unexpired firm offer can book. The same key and same enquiry/offer returns the original trade, including recovery of an overlapping HTTP retry after rollback; reusing it for different parameters conflicts. A competing distinct-key acceptance produces one success and one controlled conflict. `expectedVersion` is an optional caller read-version check.
8. `POST /enquiries/{id}/value` accepts `{market,settings,historicalFixings:{},settledThrough:null}` as documented in the pricer. Java supplies the enquiry's complete immutable terms, sends the actual numeric market inputs and snapshot ID, and preserves the full request and returned valuation/provenance including its canonical market hash. The response is `{id,request,result}`. The pricer owns canonical numerical-input hashing; Java's term hash identifies its persisted serialized contract, and the Python term hash identifies Python's canonical representation. Different hashes are labelled by provenance and are not asserted to be interchangeable.
9. `POST /trades/{tradeId}/lifecycle` accepts `{"fixings":{"2026-12-16":100}}`. It sends the accumulated immutable fixing history to the real replay boundary. Result `{tradeId,replay,obligations}`. Fixings may extend a contiguous prefix; changing a prior fixing conflicts. Unique `(trade_id,event_key)` constraints prevent duplicate obligations. A PostgreSQL enquiry-row lock serializes lifecycle replay for one trade.
10. `POST /trades/{tradeId}/obligations/advance` accepts `{"asOf":"2026-12-18","settle":false}` to mark due obligations `DUE`; `settle:true` explicitly marks due obligations `SIMULATED_SETTLED`. This controlled business date permits tests without waiting for the clock. New obligations begin `DETERMINED`. This is no payment/custody rail.
11. `POST /enquiries/{id}/revision` accepts `{terms:<complete revised contract with a new termsVersion>}` for an unbooked enquiry. The pricer validates the contract. The old version remains immutable, old offers compare as `STALE_TERMS`, and selection/instruction are cleared. A booked trade retains its actual contract.
12. `GET /enquiries/{id}` includes offers, audit and saved valuations; `GET /trades/{id}` includes obligations, audit, and the committed outbox payload. Original note purchase price includes the issue-price amount and fee. For an accumulator `originalPurchasePrice` records only its upfront fee, while `maximumPurchaseExposure` records contractual strike cash separately; there is no funded note principal.

## Correctness and learning points

`ApiController.accept → WorkflowService.accept` crosses a Spring proxy into one transaction. Trade INSERT, enquiry version change, audit and outbox commit together. `failAfterTrade:true` with `FAULT_INJECTION=true` raises a runtime exception after a flushed trade INSERT; the transaction still rolls back. A flush sends SQL; it is not a commit. Enquiry `@Version` detects competing updates, and PostgreSQL unique constraints independently enforce one trade per enquiry and one idempotency key. Outbox state `COMMITTED_NOT_PUBLISHED` explicitly means no Kafka publisher or consumer is implemented.

`WorkflowDatabaseTest.genuinelyCompetingTransactionsCannotBookTwice` holds a PostgreSQL row lock, dispatches two distinct acceptance transactions, requires observation of two concurrent lock-waiting database sessions, then releases the lock and inspects persisted trade/audit counts. It is stronger evidence than two sequential requests. `HttpPricingGatewayTest` uses a controlled real loopback HTTP server for success, error and timeout; it validates the adapter, not model prices. All database test pricing responses are declared test stubs.

`ProductTerms` demonstrates a sealed interface and immutable records, generics through typed collections, `BigDecimal` contractual money and `LocalDate` schedules. JPA entities deliberately stay outside external response models. `Offer.enquiry` and `Enquiry.offers` are lazy relationships; `open-in-view:false` keeps sessions out of response rendering. DTO construction uses explicit repository reads, avoiding accidental collection traversal per enquiry. An exercise can deliberately traverse that relation to inspect lazy-loading and N+1 behaviour; no production performance claim is made from source alone.

Known limits: development fixtures provide no authentication, legal classification or suitability decision. Quote simulation uses no HTTP issuer connection. Quote currency is constrained by exact comparison with terms, and the pricer has additional explicit supported-convention checks. Audit records are ordinary database rows, not a tamper-proof audit store. Pricing and replay HTTP calls currently hold a transaction for clarity; a production design would avoid long database transactions around remote work and retain durable workflow steps. No live issuance, confirmation, hedge book, corporate actions or event delivery is implemented.
