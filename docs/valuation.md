## Choice and evidence boundary

ORE1.8.17.0 installed and imported successfully in an isolated feasibility environment. This is installation evidence, not an ORE contract valuation. Inspection found that its documented `Autocallable_01` triggers downwards and can require a terminal holder payment, whereas `note-v1` is a funded up-trigger note. Its accumulator documentation also describes a leverage side and a grouped settlement example that must not be assumed equivalent to `acc-v1`. A new ORE scripted payoff and its convention mapping would therefore still be custom integration work. We selected explicit custom payoffs using QuantLib after inspecting these contract differences. No ORE example or ORE product adaptation is claimed as executed.

## The actual calculation path

`server.Handler.do_POST` validates the HTTP body and calls `engine.value`. `validate_request` checks the full terms, actual market numbers and state. `simulate` constructs QuantLib `BlackScholesMertonProcess`, flat risk-free/dividend curves and `BlackConstantVol`, with `Actual365Fixed`. `GaussianPathGenerator` runs on the union of future observation and payment/settlement dates. Seeded Gaussian sequences drive risk-neutral dynamics dS/S=(r−q)dt+sigma*dW. Future contractual cashflows are discounted at the supplied flat continuously compounded rate. There is no dependence on the issuer simulator.

`engine.replay` separately determines dated obligations from supplied known fixings, with Decimal half-up contractual cents. The valuation uses the same explicit contractual conditions and cent rounding, with floating-point numerical dynamics. The independent hand-worked expectations in `terms-and-payoffs.md` are the test oracle; the numerical engine is not its own contractual oracle.

For the note, NPV is remaining coupon and redemption cashflows, positive to the investor. HKD100,000 is funded notional and the par reference excluding fees. The workflow records actual firm originalPurchasePrice (issue-price cash plus disclosed fee cash), which can differ, for example100,100 or99,900 in the synthetic offers. It is separate from remaining-cashflow NPV, so an NPV around102,300 is not profit of102,300, and a comparison to par alone can misstate commercial economics. For the accumulator there is no funded principal: at each surviving fixing quantity is determined, then value includes **both** positive acquired shares at their simulated settlement spot and negative strike cash at that settlement. Reporting the cash cost alone would be wrong. Quantities remain linked to the original fixing; share price evolves through the two-day lag.

State is explicit. `asOf` is end-of-day, so observations on/before it require a contiguous `historicalFixings` prefix until termination. Future historical fixings and missing past observations are rejected. `settledThrough` excludes obligations with payment date on/before that date; null asserts none settled. A past-due unsettled obligation is payable now, shares marked at current spot, with an explicit warning and no late-interest/default model. Known past fixings, call/KO state and contractual reference levels stay unchanged in every spot bump. `ValuationTests.test_historical_termination_and_settlement` demonstrates pending note redemption, settled cash exclusion and zero post-termination spot delta. `test_pending_physical_quantity_stays_fixed_after_observation` isolates a pending physical purchase: historical89 locks20 shares, current120 values them at2400 against1800 cash, with NPV600 and delta20 in the zero-rate/volatility case; the past purchase cannot be retroactively knocked out by current spot.

Every result retains the full terms, full numerical market snapshot and ID, canonical JSON SHA256 hashes, historical fixings, settlement state, seed/path/bump settings, Python/QuantLib versions and SHA256 of payoff source. A Java-supplied `marketHash` is validated if present. The canonical form is compact sorted-key JSON as emitted by Python, retaining parsed numerical representations; a cross-language caller must reproduce that form rather than invent a different number formatter. The returned market hash is the definitive value used here. Reusing a snapshot ID with different data does not preserve its hash; persistence should retain both.

## Reproduce the numerical evidence

From repository root with Docker, `just` and network access for the first image build:

```sh
just test-pricer
just checks
```

The commands above run the pinned Python and QuantLib in containers and write evidence to `pricer/evidence/`. No host Python or virtual environment is required.

## Limits and controls

Flat single-equity Black–Scholes and synthetic teaching data omit calibration, smile/skew, stochastic rates, issuer default/funding, collateral economics, dividends as cash events, commercial costs and jurisdiction-specific calendars. Sampling error is only one source of error. This is not an executable quote, suitability assessment or production model validation. Barriers are discrete at the stated dates; no continuous monitoring is approximated. Guarantee periods, KO-date accrual and additional product fields are rejected when unsupported. Production calendars and richer variants are unfulfilled expansion requirements, not assumed hidden capabilities.

The server is one serial worker so mutable QuantLib evaluation state cannot overlap requests. Each calculation reconstructs model objects and sets its own evaluation date. For scale, use independent worker processes rather than sharing mutable objects. Requests are capped at128KiB and262,144 paths; unsupported data returns400, oversized bodies413, and unknown endpoints404. HTTP errors and access logs carry correlation IDs. These development boundaries are intentionally small; institution authentication and live connectivity are deferred.
